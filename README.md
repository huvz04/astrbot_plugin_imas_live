# AstrBot 偶像大师 LIVE 图片日历

群内提供两个查询命令：

```text
/imaslive
/imaslive 1—12
/imaslive next [imas/cg/ml/sidem/sc/gk]
/imaslive enable|disable
/imasticket
/imasticket get <活动编号>
/imasticket enable|disable
```

在 AstrBot 插件管理中使用仓库地址 `https://github.com/huvz04/astrbot_plugin_imas_live` 安装或更新。插件启动、安装和热重载后都会自动同步；若已有缓存，查询立即使用缓存，否则首次查询最多等待 8 秒，后台同步继续运行。未同步完成或失败时图片会明确提示，不会把同步失败解释成没有活动。

`/imaslive` 会生成标题为 `IM@S LIVE! · Next 30 Days` 的完整 PNG 长图，只展示从今天 00:00 起未来 30 个自然日内的演出。`/imaslive 1—12` 查询最近一次对应月份的完整自然月。每场活动有稳定的 `#编号`，可供 `/imasticket get <编号>` 查询。

官网目录偶有缺失已核验的官方活动页；插件在完整目录同步时读取最近 96 条官方新闻，最多核对 32 篇有变化的 LIVE/票务正文，从其中的实际官方专题链接补充发现。已处理正文按新闻 ID 和更新时间去重。另保留明确维护的受控 URL；不扫描或猜测地址。首次新闻覆盖和旧专题首次核验建立基线，不把历史轮次自动公告到群。

`/imasticket` 按活动分组，用一张 `Ticket Rounds` 长图展示仍未演出活动的已收录现场抽选、转售轮次；不按演出未来 30 天或申请是否开始过滤。Premium、一般一轮/二轮、转售分别保留，申请结束不删除旧轮次。每轮保留“未开始／抽选中（转售为受理中）／24小时内截止／已结束／时间待核验”状态；陈旧、抓取失败或本次官网不再列出的轮次注明“待核验”，不会继续绿色或触发通知。来源新鲜且开放的轮次为淡绿，截止 24 小时内为淡红，其余状态用中性色。活动按 LIVE 首场开始时间升序，同一活动各轮保持相邻；多日/巡演只要还有一场未开始就保留，明确绑定已过场次的轮次可隐藏。只有日期时按日本当地演出日结束后隐藏，日期未知则保守保留，不猜测开演时间。`get` 可查看历史活动和其他现场票务方式。图中只在页脚显示一次更新时间。

这不是票务代办工具。插件不会登录票务站、查询个人中签/付款/库存，也不会把先到先得、转售、配信或物販整理券当作抽选通知或截止提醒。

机票监测现由独立的 `astrbot_plugin_flight_watch` 插件承接，不再随本插件加载或运行。升级不会删除旧机票数据文件 `imas_flight.sqlite3`；如需迁移旧订阅，请先备份该文件，并在独立插件中重新配置监测任务。

## 图片与数据口径

- 六家企划沿用 birthday 插件的色彩基线，并显示紧凑的官方英文品牌名，例如 `Gakuen`、`Shiny Colors`、`Million Live!`；多企划归属的官方合同活动使用粉色。未知品牌使用灰色，不猜成合同。
- 场次优先显示专题页中已解析的场地；没有场次级场地时，回退使用官网活动目录的 `event_place` 字段。
- 同日昼夜场会各自保留；长标题自动换行，按内容自动增加图片高度，完整展示全部日期，不分页、不裁切或缩小字体。
- LIVE 图不混入抽票卡。抽票图每轮都有状态；新鲜来源的开放轮次为绿色，截止 24 小时内为淡红，未来、结束和待核验轮次为中性色。图题简洁，页脚仅保留 `update time` 和北京时间日期时间。
- 抽票卡标出活动 `#编号`、轮次、含年份的显示时区与 JST 开始/截止时间；已知的演出日期和场地会附在卡内。图片和全部官方链接以同一条消息链发送，图片在前。
- 官网专题成功核验后，如已有 LIVE 的稳定 `onsite + lottery` 轮次新增，或完整活动目录首次发现的新 LIVE 首次公布了抽选，会向已执行 `/imaslive enable` 的群发送“新增现场抽选”图文公告。公告含活动编号、活动名、轮次、北京时间/JST 起止时间、当前开放状态与官方申请链接；尚未开始也会公告，已结束轮次不发。
- `/imaslive next` 会返回最近尚未开始的场次及该日的官方出演资料。若专题页在“出演者”区实际提供完整名单图（例如 Million 14th 的 `bnr_day1.webp`/`bnr_day2.webp`），插件会校验并缓存官方原图后随详情发送；否则本地渲染已解析的官方文字名单，不从角色资料反推声优出演。
- 没有记录时仍会生成清晰的空状态图片。
- 本地 Pillow 渲染，自动寻找 Windows 微软雅黑/游ゴシック或 Linux Noto CJK/文泉驿。Linux/Docker 环境需要安装中日文字体，例如 Debian/Ubuntu 的 `fonts-noto-cjk`，也可将字体挂载到容器内并配置 `font_path`。无需浏览器。

## WebUI 配置

`/imaslive enable|disable` 与 `/imasticket enable|disable` 是 AstrBot 原生管理员命令，权限由 AstrBot 的管理员配置和指令管理统一决定；插件不维护 `admin_ids`，也不把消息平台的群管理员自动当作 AstrBot 管理员。普通用户仍可使用 LIVE、月份、`next`、抽票查询和 `get`。AstrBot 4.27.3 的指令组会强制把裸组名渲染为帮助，不能同时承载 `/imaslive` 这类默认查询；为了保留既有语法并消除重复注册告警，插件将 `imaslive`、`imaslive next`、`imaslive enable` 等注册为独立的原生命令。它们可在 WebUI 的“指令管理”中分别查看、启停或重命名。私聊不会设置订阅。`/imaslive enable` 同时控制 LIVE 开演前一小时提醒和新增现场抽选公告；`/imasticket enable` 只控制抽票截止前 24 小时与 1 小时提醒。两种订阅分别按完整 UMO 保存，互不影响。已订阅群在节点后短暂的发送或调度故障会在默认 20 分钟恢复窗口内重试；不会跨到下一节点、不会在截止后补发，重新开启订阅也不会回放旧提醒。

| 配置 | 默认值 | 作用 |
|---|---:|---|
| `enabled` | `true` | 官网后台同步与自动提醒总开关；查询仍可读取缓存。 |
| `white_umos` | `[]` | 旧版抽票白名单，仅首次迁移到抽票订阅；绝不隐式开启 LIVE。 |
| `live_reminder_enabled` | `true` | 开关 LIVE 开演提醒。 |
| `live_reminder_before_hours` | `1` | 官网明确开演时间换算到北京时间后，提前一小时提醒。 |
| `ticket_new_announcement_enabled` | `true` | 开关官网新增的现场抽选公告，发送到 LIVE 订阅群。 |
| `reminder_enabled` | `true` | 开关现场抽选截止提醒。 |
| `ticket_reminder_hours` | `[24, 1]` | 抽票截止前 24 小时和 1 小时各提醒一次。 |
| `brands` | `[]` | 图片和提醒的企划代码筛选；空表示全部。 |
| `display_timezone` | `Asia/Shanghai` | 图片主展示时区。 |
| `font_path` | 空 | 自定义中日文字体文件。 |

提醒检查每 5 分钟独立运行，不等待较慢的官网同步。LIVE 仅对官网给出明确时区和开演时间的场次触发；官网常用 JST 会先转换成北京时间再按绝对时刻计算。新增抽选公告只比较已经成功核验过的同一专题来源中的稳定轮次；首次安装、升级后的首次成功核验、分批首次覆盖旧专题，以及群晚开启/重新开启都只建立基线，绝不回放历史轮次。抽票截止提醒仅限已开始、来源新鲜的 `onsite + lottery`；24 小时和 1 小时节点独立去重，晚开启不会补发错过的节点。

查询和五分钟检查还会有界复核“旧申请已结束、LIVE 尚未开始”的活动，以发现后续先行，不再仅等待每小时轮转。按专题最后尝试时间公平轮换，失败至少退避五分钟。官网新闻只有明确的现场票务标题、申请起止时间和真实 reception 链接才补充轮次；按活动与 reception 去重，独立保存核验来源和时间，新闻成功不会把旧轮或专题根页标成新鲜。转售只进入现场票务列表，不参加抽选新增公告或截止提醒。

新增抽选公告使用独立的 `ticket_new` 待发送记录，按群和稳定轮次去重，不与 24 小时/1 小时截止提醒或 LIVE 开演提醒混用；标题、时间或链接的小修不会当作新轮次。每群、每个实际截止时间和提醒节点最多成功发送一次；LIVE 按群、场次和开演时刻去重。失败投递可重试、重启可恢复，关闭订阅或轮次结束后不再发送。外部消息与本地数据库无法构成单一原子事务，因此不会声称严格 exactly-once。

## 来源与降级

官网匿名 CMS 令牌仅在内存中使用，不写入日志或 SQLite。默认每 6 小时完整刷新活动目录和新闻发现，每小时轮换核验最多 12 个专题，并跟随专题内真实的日程、票务和出演链接。新闻变更、正在进行和未来演出的活动优先；老旧无日期失败来源进入低优先级队列，并保留历史轮换名额。每 5 分钟独立检查时，最多额外复核 4 个已知的陈旧开放或临近开始专题，每个活动只占一个名额。手动查询也有界复核已知开放来源。目录中明确列举的演出日可先展示；连续日期范围不会擅自展开为每日演出。

插件保存结构化事实、短证据片段、内容 hash 与官方链接。抓取失败保留旧缓存，并暂停该来源的提醒；其他来源成功不会使失败来源被当作最新数据。完整目录异常或分页不全不会覆盖为成功空结果，仍会尝试刷新已有专题。初次目录就绪后，票务信息还会继续补齐。每轮同步日志包含候选总数、未覆盖及待核验数、上次目录成功时间和上次专题成功核验时间；全部专题失败时不会更新成功时间。没有部署端日志时，不能仅凭代码推断你的服务器定时任务是否正常运行。

已核实官方前端使用的 `Article/get` 正文接口：动态 `/live_events/` 使用 `detail_page`，官方新闻按 `page` 取正文；动态正文从 CMS 读取，静态 `/live_event/` 读取实际 HTML。解析覆盖新旧 `dl`、分组票务字段、accordion 和 CMS 带明确标签的组件；申请、结果与付款时间分别读取，同轮不同席种的申请链接各自保留。未能解析的来源保留为待核验，而非虚构日期或截止时间。

## 本地验证与预览

在仓库根目录运行（需 Python 3.10+ 和可用的中日文字体）：

```text
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
python -X utf8 scripts/audit_official_sources.py
```

离线样本包含在 `tests/fixtures`，新版官网语义片段覆盖在 `tests/test_ticket_sources.py`。测试涵盖专题链接遍历、多段落多日演出、完整目录保存、新闻发现、动态正文、队列轮换、令牌刷新、异常分页、首次查询等待、热重载、月份跨年/闰年、30 天边界、未来/开放/结束轮次同屏、远期 LIVE 当前抽选、来源陈旧状态与提醒不误发、图片排版，以及新增抽选的来源基线、群路由、晚开启、去重和失败重试。官网审计脚本使用临时数据库，不订阅或发送消息；结果和一张预览图生成在忽略的 `previews/_generated/official-audit` 目录。

v0.4.11 于北京时间 2026-10-09 实测官方目录、最近新闻及 10 个重点专题，并额外核对 SideM ～Wanna step in～ 两城市 8 场的开演时间、城市票务绑定。本轮有界列表得到 12 个活动、18 个现场轮次：11 个开放、6 个结束、1 个起止时间待核验；已全部开始的活动不再进入票务长图，不能据此声称已经覆盖官网全部票务。已核实 [CLASH M@TCH!!](https://idolmaster-official.jp/live_event/deremilli_clashmatch/) 的 2027 年 2 月 27、28 日两场演出、一般会员先行（2026-10-07 12:00 JST 至 11-01 23:59 JST）和旧 Premium 两轮，官方新闻 `01_20072` 的一般先行与专题一致。本次修复旧轮结束后未来 LIVE 被查询/五分钟复核跳过的问题；当前页面可正常解析，未复现解析失败或 8 页上限。88 项离线回归通过；部署端实际版本、定时任务和群投递仍需运行日志确认，不能把该刷新缺口当作已证实的生产故障根因。
